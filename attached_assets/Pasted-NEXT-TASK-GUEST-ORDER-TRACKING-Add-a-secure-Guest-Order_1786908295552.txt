NEXT TASK — GUEST ORDER TRACKING

Add a secure Guest Order Tracking feature to the existing storefront.

IMPORTANT:
- Inspect the existing Order model, order status system, order confirmation page, customer order history, and authentication architecture first.
- Reuse the existing order status logic and design.
- Do not create a duplicate order tracking system.
- This feature is specifically for customers who placed orders without signing in.

1. TRACK ORDER PAGE

Create a dedicated "Track Your Order" page.

Allow a guest customer to enter:

- Order Number
- Email address or phone number used when placing the order

Then provide a "Track Order" button.

Do not require the customer to create or sign into an account.

2. SECURITY

Do NOT allow an order to be retrieved using only the order number.

Require a second piece of information that matches the order, such as the customer's email or phone number.

The backend must validate this information before returning order details.

Do not expose:
- Another customer's personal information
- Full payment information
- Internal admin information
- Sensitive database fields

3. ORDER STATUS

After successful verification, display the existing order status/progress using the site's existing order status design.

Use the existing statuses and terminology already implemented.

Show useful information such as:

- Order number
- Order date
- Current order status
- Pickup or Delivery
- Relevant delivery/pickup information
- Ordered items
- Order total
- Payment status

Do not expose unnecessary sensitive information.

4. STATUS HISTORY

If the existing system already stores order status history, display the relevant customer-safe history/timeline.

Example:

✓ Order Placed
✓ Payment Confirmed
✓ Processing
○ Out for Delivery
○ Delivered

Use the actual status history rather than creating fake timeline data.

5. GUEST ORDER CONFIRMATION

After a guest successfully places an order, provide a clear way to access the tracking page.

The order confirmation page should also clearly show the order number and explain how the customer can track the order later.

Do not require account creation after placing the order.

6. NAVIGATION

Add "Track Order" to an appropriate existing storefront location, such as the navigation/footer, without cluttering the interface.

Reuse the existing navigation structure.

7. ERROR HANDLING

Provide clear messages for:

- Order not found
- Email/phone does not match
- Invalid input
- Server error

Do not reveal whether an order exists when the verification information is incorrect in a way that could help someone enumerate orders.

8. RATE LIMITING

Protect the guest tracking endpoint against excessive attempts.

Reuse the existing rate-limiting/security infrastructure if available.

9. RESPONSIVE DESIGN

Ensure the tracking page works properly on:

- Mobile
- iPhone/Safari
- Android
- Desktop

10. TEST

Verify:

- Guest can place an order.
- Guest receives an order number.
- Guest can track the order using the correct verification information.
- Incorrect email/phone cannot access the order.
- Another customer's order cannot be accessed.
- Order status updates are reflected correctly.
- Existing authenticated customer order tracking/history remains functional.
- Existing admin order management remains functional.
- Frontend and backend builds pass.

Keep the implementation modular, secure, scalable, and consistent with the existing application.

Do not modify unrelated features.
