NEXT TASK — PRODUCT DISCOUNT FEATURE

Improve the EXISTING Admin Product Creation/Edit system by adding product-level discounts.

IMPORTANT:
- Inspect the existing product, cart, checkout, and order pricing implementation first.
- Reuse the existing architecture and UI. Do not create a separate pricing system.
- Do not implement coupons, flash sales, bulk discounts, or other discount features.
- Do not hardcode prices or discounts.

1. ADMIN

Allow admin to optionally add a discount to a product.

Support:
- Percentage discount
- Fixed amount discount

Admin must be able to:
- Add discount
- Edit discount
- Remove discount

Validate the discount on both frontend and backend.

Do not allow invalid, negative, or greater-than-product-price discounts.

2. CUSTOMER PRICE DISPLAY

When a product has a discount, display:

₦18,000  ~~₦20,000~~

The discounted price should be prominent and the original price should have a visible strikethrough.

IMPORTANT:
- Do NOT display "10% OFF".
- Do NOT display the discount percentage or discount amount beside the price.
- The strikethrough original price is enough.

When there is no discount, display only the normal price.

Use this consistently across existing:
- Product cards
- Product details
- Search results
- Category listings

3. PRICING

Keep the pricing calculation centralized in the backend/service layer.

The backend must be the source of truth.

Ensure the discounted price is correctly reflected in:
- Cart
- Checkout
- Order creation

Do not trust prices sent by the frontend.

4. ORDERS

When an order is created, save the actual price charged at that time.

If the admin later changes/removes the discount, existing orders must NOT change.

Reuse the existing OrderItem price snapshot structure if available.

5. DELIVERY FEE

Keep product discounts separate from the existing delivery fee.

Example:

Product after discount: ₦18,000
Delivery fee: ₦2,000
Total: ₦20,000

6. DATABASE

Inspect the existing Prisma schema first.

If necessary, add clean discount fields such as:

- discountType
- discountValue

Keep the original product price.

Create the required Prisma migration and ensure existing products continue working.

7. SECURITY

Only authorized admins can manage discounts.

Enforce this on the backend.

Customers must not be able to manipulate product prices, discounts, or order totals.

8. TEST

Verify:

- No discount works normally.
- Percentage discount works.
- Fixed discount works.
- Invalid discounts are rejected.
- Prices display correctly with strikethrough.
- Cart and checkout use the correct price.
- Orders preserve the price charged.
- Changing a discount does not affect old orders.
- Delivery fee remains separate.
- Mobile and desktop layouts work.
- Frontend and backend builds pass.

Preserve the existing design, architecture, and functionality. Do not modify unrelated features.
